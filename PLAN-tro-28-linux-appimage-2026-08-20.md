# План исправления TRO-28: Linux AppImage и updater

**Дата и время:** 20.08.2026, 23:27:57 MSK  
**Автор:** Codex (`/root`)  
**Статус:** согласован пользователем командами «ltkfq»/«делай» 20.08.2026.

## Подтверждённые дефекты

1. AppImage `0.9.25` содержит хук `export GDK_BACKEND=x11`, из-за которого окно остаётся невидимым в XWayland на Ubuntu 26.04 / GNOME Wayland / Intel Arc.
2. При запуске без корректной переменной `APPIMAGE` Tauri Updater может записать скачанный AppImage поверх внутреннего ELF-бинарника и разрушить распакованную либо пакетную установку.
3. Страница загрузки предлагает AppImage раньше `.deb`, хотя для Ubuntu/Debian пакет `.deb` безопаснее и не зависит от FUSE 2.

## Реализация

1. Во время перепаковки AppImage заменить принудительный X11 на `GDK_BACKEND=${GDK_BACKEND:-wayland}` и добавить CI-проверку готового образа.
2. Разрешать автоматическую установку обновления на Linux только при заданной переменной `APPIMAGE`, указывающей на существующий файл; повторно проверять условие непосредственно перед установкой.
3. Для `.deb`, распакованного AppImage и локальной сборки показывать ручной режим обновления со ссылкой на страницу загрузки, не сохраняя доступный для установки updater-resource.
4. Добавить Rust- и JavaScript-регрессионные тесты.
5. Сделать `.deb` основным Linux-вариантом на публичном сайте, AppImage оставить переносимым запасным вариантом с честным пояснением про FUSE 2 и автообновление.
6. Выпустить исправление как `v0.9.26`, проверить подписанные артефакты, updater manifest и публичные страницы.

## Приёмка

- готовый AppImage не содержит жёсткого `GDK_BACKEND=x11`, по умолчанию запускается через Wayland и допускает ручной `GDK_BACKEND=x11`;
- запуск без `APPIMAGE` не предлагает и не выполняет автоустановку, внутренний ELF не изменяется;
- штатно запущенный AppImage принимает подписанное обновление;
- `.deb` стоит первым в Linux-блоке сайта и явно помечен как рекомендуемый вариант для Ubuntu/Debian.
