### 1.3 Почему у пользователя «пропали все карты», а не часть

`makeBaseLayer(name)`:
1. спец-случаи (`Яндекс Схема`, `Яндекс Гибрид`, `Спутник Bing`, `Гибрид Bing`) — прямые URL, работают;
2. **иначе** — поиск в загруженном каталоге и `entry.proxy` → мёртвый DE2;
3. хардкод-fallback — только если каталог **не** загрузился.

Каталог загружается штатно (200), поэтому шаг 3 недостижим, и все слои из каталога —
включая бесплатные OpenStreetMap/OpenTopoMap — идут на мёртвый адрес. Работают только
офлайн-карты (MBTiles) и четыре спец-слоя, если они остались в списке (см. 1.5).

### 1.4 Админский выбор карт — система есть и работает

- Каталог: `/opt/tnd-tiles/data/tile_catalog.json`, **169 источников, включено 25**
  (17 базовых + 8 оверлеев), `updated_at` 09.08.2026 — после переезда каталог не трогали.
- Админка: `https://trophynav.ru/sync/admin/` (Basic Auth, креды в `/etc/tnd-sync/secrets.json`),
  вкладка **«Карты»** (`data-tab="tiles"`).
- API: `GET /api/admin/tiles`, `POST /api/admin/tiles/:id/toggle`, `POST /api/admin/tiles/batch`,
  `PATCH /api/admin/tiles/:id`, `POST /api/admin/tiles/refresh` (запускает `scripts/parse_zmp.py`,
  python 3.14 на месте, зависимости — только стандартная библиотека). Проверено: `/api/admin/tiles`
  отдаёт 200 и локально, и через домен с Basic Auth.
- Отдача клиентам фильтрует по `enabled` в обоих форматах: `/api/tiles/catalog` (Android)
  и `/api/tiles-catalog.json` (Desktop).

**Вывод:** механизм жив, но эффективен сейчас только для Android. Для десктопа админка
управляет *списком названий*, а тайлы по нему не грузятся из-за 1.2. Разделения
«для Android / для Desktop» в каталоге нет — флаг `enabled` общий.

### 1.5 Побочные дефекты десктопа, найденные попутно (не связаны с переездом)

1. **`FREE_LAYER_KEYS` рассинхронизирован с каталогом.** В коде `{'osm','topo','cyclosm','osm_hot'}`,
   в каталоге id `osm_standard`, `opentopomap`, `cyclosm` (выключен). Совпадений ноль →
   блок «Бесплатные карты» не перестраивается (остаётся статический HTML), а все 17 карт
   каталога уезжают в Premium-секцию, то есть закрываются лицензией.
2. **Спец-слои исчезают из UI.** `buildLayerUI()` перезаписывает Premium-контейнер именами из
   каталога, а имён `Яндекс Схема`, `Яндекс Гибрид`, `Спутник Bing`, `Гибрид Bing` в каталоге нет
   (там `Яндекс Карты`, `Яндекс Спутник`, `Яндекс Гибрид (точный)`). Единственные рабочие сейчас
   слои пользователю не видны.
3. Офлайн-скачивание берёт `entry.url` (прямой адрес источника), а не прокси — работает,
   кроме Wikimapia (п. 1.2, строка 8907).

## 2. План работ

### Этап 0. Подготовка (без правок кода) — 15 мин

1. Проверить в GitHub secrets репозитория `UPDATES_DEPLOY_HOST` / `UPDATES_DEPLOY_USER` /
   `UPDATES_DEPLOY_SSH_KEY` / `UPDATES_DEPLOY_KNOWN_HOSTS`: должны указывать на `104.171.128.204`.
   Если нет — обновить и убедиться, что деплой-ключ пущен на Alpha-KM.
2. Проверить `vars.UPDATES_DEPLOY_PATH` = `/var/www/updates/latest-desktop.json`.
3. Обратимая проверка админки: выключить и включить обратно один второстепенный источник,
   убедиться, что `enabled_count` меняется и оба каталожных роута реагируют. (Правка боевых
   данных — делаю только по команде.)

### Этап 1. Правка десктопа — 30 мин

В `ui/index.html` ввести единую константу и заменить пять мест:

```js
const API_BASE = 'https://trophynav.ru';   // единственная точка входа
```

| Место | Было | Станет |
|---|---|---|
| `4745` | `const SERVER = 'http://87.120.84.254:9222'` | `API_BASE` |
| `4895` | Wikimapia proxy URL | `${API_BASE}/tiles/wikimapia_hybrid/...` |
| `8907` | Wikimapia в офлайн-загрузчике | то же |
| `12133` | `LICENSE_SERVER` | удалить; `LICENSE_API_BASES = [API_BASE]` |
| `14096` | `LIVE_API_BASE` | `API_BASE` |

Заодно перевести `SYNC_SERVER` и оба `fetch('https://trophynav.ru/api/tiles-catalog.json')`
(строки 4794, 4813) на ту же константу, чтобы адрес был в файле ровно один раз.

### Этап 2. Починка витрины слоёв — 30 мин

1. `FREE_LAYER_KEYS` → `{'osm_standard','opentopomap','cyclosm','osm_hot'}` (сверить с каталогом).
2. `buildLayerUI()` — не терять спец-слои: либо добавлять `Яндекс Схема` / `Яндекс Гибрид` /
   `Спутник Bing` / `Гибрид Bing` к списку из каталога, либо (чище) завести им записи в каталоге
   и убрать спец-кейсы из `makeBaseLayer`.
3. Решить по Bing/Яндексу: оставить прямые URL или пустить через прокси Alpha-KM (прокси даёт
   кэш и снимает вопрос доступности источника у клиента).

Этап 2 можно вынести в отдельный релиз, если хочется выпустить исправление быстрее.

### Этап 3. Проверка — 30 мин

`cd src-tauri && cargo check && cargo tauri dev`, затем вручную:
карта из бесплатного блока, карта из Premium, Яндекс, оверлей Wikimapia, скачивание офлайн-района,
экран лицензии, живой мониторинг (`/api/live2/devices`), sync push/pull.
В DevTools — ноль запросов на `87.120.84.254`.

### Этап 4. Релиз v0.9.23 — 1–2 ч (в основном ожидание CI)

1. Версию поднять в `src-tauri/tauri.conf.json` и `Cargo.toml`, тег `v0.9.23`, пуш.
2. После CI: `curl -s https://trophynav.ru/api/updates/latest.json` — версия 0.9.23, валидные
   `signature`/`url`.
3. Скачать с GitHub Release и залить на Alpha-KM в `/var/www/trophy-site/releases/` под именами
   `trophy-navigator-desktop_0.9.23_x64-setup.exe` и `..._amd64.AppImage`.
4. Обновить `index.html` и `download.html` на Alpha-KM (перед правкой — `.bak` с датой).
5. Контроль: `curl -sI https://trophynav.ru/releases/trophy-navigator-desktop_0.9.23_x64-setup.exe` → 200.
6. Финальный sign-off — Том (по канону перед продом).

### Этап 5. Документация — 20 мин

1. `AGENTS.md`: переписать релизный чек-лист под Alpha-KM (хост, пути, `ssh alphakm-ru`).
2. `project-dossier.md`: убрать `http://87.120.84.254:9222/admin/`, вписать `https://trophynav.ru/sync/admin/`
   и указатель на vault (без значений).
3. `notes/Проекты/trophy-navigator.observations.md` — запись о завершении переезда десктопа;
   `Home/Инфраструктура/Домены и точки входа.md` — снять формулировку «лицензии и sync проксируются
   на DE2»: по факту `/api/` и `/sync/` в nginx Alpha-KM идут на локальный 9222.
4. `journal-add` в `shared-context.md`.

### Этап 6. Необязательное

- **Старые клиенты (≤0.9.22).** Тех, у кого автообновление включено, чинит сам релиз — updater
  ходит на `trophynav.ru` начиная с v0.9.3. Поднимать на DE2 слушатель на 9222 с проксированием
  на Alpha-KM смысла мало: у части операторов DE2 недоступен, а вешать новое на фильтруемый IP —
  ровно та ошибка, из-за которой всё и упало. Рекомендую не делать.
- Архив `/opt/tnd-sync` на DE2 — вывезти в бэкап и погасить, чтобы не осталось второй копии данных.
- Долг из RaceNav-переезда, актуальный и здесь: в `/opt/tnd-live/config.json` SSH-пароль root
  латвийского сервера лежит в открытом виде (файл 0600) — вынести в secrets или перейти на ключ.

## 4. Риски

| Риск | Митигация |
|---|---|
| CI кладёт манифест на DE2 → обновление не доедет | Этап 0 п.1 до тега |
| Кэш тайлов в приложении привязан к слою, а не URL — старые записи могут отдавать пустоту | При смоуке проверить очистку кэша слоя; при необходимости добавить bump версии кэша |
| Правка витрины слоёв (этап 2) затрагивает UI и может задеть сохранённые настройки пользователя (`hidden`, активный слой) | Проверить миграцию ключей в `localStorage`, при несовпадении — мягкий сброс только списка скрытых |
| Alpha-KM — единственная точка: там же DNS-ключ reg.ru и сертификаты | Отдельная задача (резервирование), в этот план не входит |
